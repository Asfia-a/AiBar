## 2. 怎么跑起来

三个进程，端口固定：

```powershell
# 方式一：一键脚本（推荐，会顺手检查 Redis/MySQL）
.\start-dev.ps1

# 方式二：手动
cd ai-tavern;      $env:SPRING_PROFILES_ACTIVE='local'; mvn spring-boot:run   # 8080
cd ai-tavern-web;  npm run dev                                                # 5173
cd ai-tavern-admin; npm run dev                                               # 5174
```

**PowerShell 坑**：`-Dspring-boot.run.profiles=local` 会被拆成两个参数导致启动失败，必须用环境变量。
**首次启动坑**：`mvn spring-boot:run` 需要联网拉插件依赖，拉过一次之后才能 `-o` 离线跑。

账号：管理端 `admin / admin123`；用户端自行注册。

## 4.2 接手第二轮补的（采样参数补全）

对标 SillyTavern 的采样配置，把原来只有 temperature / top_p / max_tokens 的三档补成完整一套：

- **表与实体**：`t_character` 新增 `top_k` / `frequency_penalty` / `presence_penalty` / `repetition_penalty` / `stop_words`（迁移脚本 `sql/migration_2026-10-23_sampling.sql`，两份 schema.sql 已同步）；入库前在 `CharacterService` 统一归一——中性值（top_k=0、惩罚=0、重复惩罚=1）一律存 NULL，表示「不下发、交给服务端默认」
- **请求体**：`AiModelService` 引入 `ChatParams` 参数对象，`streamChat` 换签名；请求体组装抽成静态 `buildRequestBody`，配 6 个单测（`AiModelServiceSamplingTest`）
- **关键取舍——`ai.model.extended-params: auto`**：`top_k` 和 `repetition_penalty` 不是 OpenAI 标准参数，云端网关（OpenAI/DeepSeek）遇到不认识的字段是直接 400，不是忽略。所以 auto 模式下只有 base_url 指向本机/局域网（Ollama、vLLM 等）才真正下发，云端自动跳过；`frequency_penalty` / `presence_penalty` / `stop` 是标准参数，任何时候都发
- **人设快照**：采样参数随 `prompt_snapshot` 一起冻结，作者事后调参不影响老会话的手感（与冻结人设同一逻辑）
- **前端**：角色编辑页「模型参数」卡新增默认收起的高级采样区（4 个滑杆 + 停止词输入，支持 `\n` 转义），并明确提示 top_k/重复惩罚的生效范围
- 停止词用 `|` 分隔、最多 4 条（OpenAI 兼容接口的上限）

## 4.3 接手第三轮补的（消息操作：多版本 / 编辑 / 分支）

对标酒馆的 swipe（滑动重生），把「重新生成」从「删掉重来」升级成「多版本」：

- **表**：`t_chat_message` 加 `swipe_count` / `swipe_index`；新增 `t_message_swipe`（`unique(message_id, idx)`），迁移脚本 `sql/migration_2026-10-23_swipe.sql`
- **不再删消息**：`regenerate` 直接委托给新的 `swipe`——第一次滑动先把原回答存成 idx=0，再追加 idx=1 并设为当前；旧版本永远滑得回去
- **提示词侧**：`buildPrompt` 多了「截止消息 id」参数，滑动时把目标消息及其之后的消息排除，否则模型会看到自己上一版回答变成续写
- **切换版本**：`POST /api/chat/messages/{id}/swipe/select`，纯读库、不调模型、不扣积分
- **编辑**：`PUT /api/chat/messages/{id}`，用户与助手消息都可改；只改文本、不动计费，但**要走一遍敏感词同步审核**，否则这里就是绕过审核的后门；改的是最后一轮时同步会话摘要
- **分支**：`POST /api/chat/messages/{id}/branch`，以某条消息为终点复制出新会话，人设快照与作者注释一并带过去，原会话不动
- **计费重构**：`finishChat` 与 `finishSwipe` 共用一个 `charge()` + `logToken()`，避免两套扣费逻辑漂移
- **前端**：消息悬停操作条扩成「复制 / 上一版 / 2-3 版本号 / 下一版 / 再生成一版 / 编辑 / 分支」；编辑用对话框；失败时把气泡回滚成原版本，不会丢内容
- 新增 `ChatMessageOpsTest` 7 个用例：首次滑动备份原回答、摘要同步、编辑不动计费、敏感词拦截、空内容拒绝、越权拦截、用户消息不能滑

## 4.4 接手第四轮修的（两个真 bug）

**1. `Unknown column 'status' in 'where clause'`（聊天直接 500）**

`ModelConfigMapper` 读写的是 `status / temperature / top_p / max_tokens`，但建表脚本里是 `enabled / temperature_default`，而且没有 `top_p`、`max_tokens`。代码、管理端表单、实体三边一致，只有表结构是旧的，所以第一次真的去取模型配置就炸。

- 新增 `sql/migration_2026-10-23_model_config.sql`：`enabled → status`、`temperature_default → temperature`，补 `top_p`、`max_tokens`
- 两份 `schema.sql` 同步
- 验证：`SELECT * FROM t_model_config WHERE status=1` 正常；管理端 GET/PUT `/api/admin/model/config` 均 200

**2. SSE 报错时客户端只看到「连接已断开」**

`stream()` / `swipe()` 出错时原来调 `completeWithError(e)`。响应已经是 `text/event-stream` 且已提交，Spring 会再派发一次 `/error`，试图把 `Result` 序列化成 SSE，结果报 `HttpMessageNotWritableException`，前端拿不到真实错误原因。

- 抽出 `failStream(emitter, e, tag)`：先写一条 `event: error`，再 `emitter.complete()`
- 验证：API Key 失效时，客户端能收到 `event:error` + 具体原因（HTTP 200），日志里不再有转换器报错

**顺带发现（不是代码问题）**：`application-local.yml` 里的 `ai.model.api-key` 属于 `claudex.org` 网关，而库里 `t_model_config.base_url` 指向 `api.deepseek.com`，两者不匹配 → DeepSeek 返回 `Authentication Fails`。要么把 key 换成 DeepSeek 的，要么把模型配置改回 `https://claudex.org/v1` + `deepseek-v4-flash`（本机已按后者改好，实测可正常流式）。想零成本演示就把 local 里的 key 清空，后端会自动降级为本地模拟流。

## 5. 提示词引擎（本轮新增，最重要的可讲点）

对标 SillyTavern，补齐了三件最影响聊天手感的东西：

| 能力 | 落点 |
|---|---|
| 世界书（关键词激活的设定库） | `prompt/WorldInfoService` + 表 `t_world_info_entry` |
| 作者注释（可定位、可限频的强指令） | `prompt/PromptEngine` + 会话字段 `author_note/an_depth/an_frequency` |
| 提示词模板外置 | `src/main/resources/prompts/*.md` + `prompt/PromptTemplateService` |

拼装顺序：`主提示 → 世界书(before_char) → 世界书(after_char) → 历史对话（含 in_chat 深度注入）→ 收尾指令(Post-History，永远最后)`，预算按段分配，超了从最早的历史开始丢。

想调提示词措辞：直接改 `resources/prompts/main.md`，不用重新编译 Java。
设计说明与后续规划：`docs/酒馆聊天能力对标.md`。

**在哪里用**（答辩演示顺序建议）

1. 角色详情页 → 「世界书」按钮 → 新建两条：一条填触发词 `钟楼,敲钟`、位置「人设后」；一条开「常量」、内容写叙述风格。
2. 在页面下方「命中预演」里输入一句话（带/不带触发词各试一次），能看到命中条数、token 占用立刻变化 —— 这一段不用 API Key，最稳。
3. 回到对话页 → 右上角「作者注释」→ 写一句「语气更克制，不要主动推进剧情」，深度 0 保存；顶栏出现标记后再发一句，对比前后回复。
4. 接口清单：`GET/POST /api/characters/{id}/worldbook`、`POST /api/characters/{id}/worldbook/preview`、`GET|POST /api/characters/{id}/worldbook/export|import`、`PUT /api/characters/{id}/worldbook/reorder`、`POST /api/worldbook/global`、`PUT|DELETE /api/worldbook/{id}`、`POST /api/worldbook/{id}/toggle`、`GET|PUT /api/chat/sessions/{id}/author-note`。
5. 收尾指令：角色编辑页「收尾指令」卡写一句「每段回复不超过 300 字」保存 → 新建会话问一个会写长段的问题，对比回复长度；老会话不受影响（快照冻结，这本身就是个可以讲的点）。

## 9. 决策记录（别轻易推翻）

- **为什么 shadcn-vue 而不是 Element Plus**：组件源码进仓库可改可讲，视觉上限高，答辩能指着文件说。管理端没换是因为后台表格用 EP 更省事。
- **为什么只改用户端**：管理端 1400 行全是表格表单，重写不产生答辩价值。
- **为什么 ECharts 按需**：整包 1.14 MB → 0.55 MB，构建告警也消了。
- **世界书按需激活而不是全量塞**：省 token，也是「用不起 API」时最直接的省法。
- **提示词模板放 md 不放数据库**：改措辞不用重启、能进 git diff，答辩时演示「改一句就变」。
- **全局世界书挂在 user_id 上**：`character_id IS NULL` 的条目按创建者隔离，引擎内置条目 `user_id` 留空即人人可用；这样既支持「我自己的写作习惯全局生效」，又不会把别人的设定塞进你的上下文。
- **世界书预演不调模型**：命中判断是纯本地纯函数，所以管理页可以反复点、答辩现场可以随便演示，不怕花钱和超时。
- **收尾指令放历史之后**：离模型这次回复最近、约束力最强，语义与 SillyTavern 的 Post-History Instructions 一致；它写进角色卡并随快照冻结，作者事后改措辞不影响老会话。
- **世界书导入不含 id**：JSON 里带 id 会诱导「按 id 还原」，跨库跨角色必炸；一律新建，逐条走 normalize 兜底，脏条目跳过不阻塞整批，返回计数让前端提示。
- **亮色主题几乎零成本**：重写时令牌就按 shadcn 惯例给了 `:root` 亮色段、暗色只是 `.dark` 覆盖，所以补主题只花了「挂类 + 切换按钮 + 防闪内联脚本」的功夫，不存在第二套令牌要维护。
- **主题偏好内联在 index.html**：main.js 是 module 加载，等它执行时首帧早画完了，会闪屏；一段内联脚本在解析期就把 `.dark` 挂好。

## 10. 接手第一天的建议

1. `mvn -o test` + `npm run build` 先跑一遍，确认基线（应分别看到 90 个用例全绿、构建成功）。
2. 配一个便宜模型或本地 Ollama（`base_url=http://127.0.0.1:11434/v1`），走一遍：注册 → 建角色 → 建世界书 → 对话 → 调作者注释 → 改写小说 → 发布 → 社区点赞评论。
3. 按第 5 节末尾的四步演示一遍世界书与作者注释，确认「预演命中 → 对话生效」这条线肉眼可见。
4. 再做答辩材料：技术点讲稿、演示数据、README 截图（`.shots/` 里已有真实后端跑的 `real-*.png` 可参考）。
